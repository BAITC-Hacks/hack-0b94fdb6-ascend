# Freedom Graph · Telegram Bot

Изолированный MVP личных автоматических оповещений для аналитиков команды. Все файлы находятся в `TelegramBot/`; frontend, backend и AI-agent не изменяются. Python 3.11+ на macOS/Linux, только стандартная библиотека, ничего устанавливать не нужно.

## Как это работает

1. Пользователь открывает **@FreedomGraphbot** и нажимает Start.
2. Отправляет `/activate КОД`, полученный у команды. Бот сам получает его числовой Telegram ID из сообщения Telegram — вручную собирать ID не нужно. "52rnL5eBPkdaZoZHOW5gUKvscgN4xavn" - код для активации бота
3. После активации новые оповещения приходят **автоматически в этот личный чат**. Группа или канал не нужны.
4. `/pause` и `/resume` управляют только своей подпиской; `/stop` отключает её и завершает доступ.

Идентификация означает привязку к Telegram-аккаунту и проверку общего кода команды. Это **не проверка личности сотрудника, не банковский SSO и не подтверждение должности L2**. Владелец случайно сгенерированного кода может активировать доступ. Код передавайте только коллегам; при утечке замените `TEAM_ACCESS_HASH` и перезапустите процесс — старые активации станут недействительными. Для промышленного использования нужны согласованные индивидуальные права доступа, отзыв доступа и аудит.

## Безопасное подключение

На Mac можно открыть `TelegramBot/launch.command` двойным щелчком. При первом запуске он попросит новый токен скрытым вводом, создаст настройки, опубликует меню команд и запустит бота. При следующих запусках использует сохранённый `.env`. Окно должно оставаться открытым; сон/выключение ноутбука останавливает работу. Это локальный запуск, не круглосуточный хостинг.

Токен, опубликованный в переписке, считайте раскрытым. В **@BotFather** выполните `/revoke`, выберите @FreedomGraphbot и получите новый токен. Не отправляйте новый токен в чат, GitHub или frontend.

Из корня репозитория:

```sh
python3 -m TelegramBot.setup
```

Введите новый токен в локальном терминале: ввод скрыт. Скрипт создаст `.env` с правами `0600`, сгенерирует случайный 192-битный код активации и один раз покажет его владельцу в терминале. Сохраните код в менеджере паролей и передайте команде защищённым способом. В `.env` хранится только SHA-256 кода. Существующий `.env` не перезаписывается.

Проверьте `BACKEND_URL` в локальном `.env` (по умолчанию `http://127.0.0.1:8000`). Доступный backend запускает его владелец: бот его не создаёт, не запускает и не изменяет.

```sh
python3 -m TelegramBot --configure
python3 -m TelegramBot
```

Первая команда публикует описание и меню команд Telegram. Вторая запускает мониторинг и обработку личных сообщений. Если настроен чужой webhook или запущен второй обработчик, бот остановится с ошибкой, не удаляя чужие настройки.

Откройте [бота](https://t.me/FreedomGraphbot), нажмите Start, отправьте `/activate КОД`. Сообщение с кодом бот попытается удалить; удаление не гарантировано. Код не записывается в логи/БД. После пяти неверных попыток для одного Telegram ID действует блокировка на 15 минут.

Процесс должен оставаться запущенным с доступом к backend и Telegram. При выключении/сне ноутбука оповещения не отправляются. Постоянный хостинг в этом MVP **не настроен**.

## Источник и смысл сигнала

- Только GET `/api/v1/overview` → `/api/v1/graph` → `/api/v1/overview`. Совпадение run_id, успешный статус, числа узлов/связей и формат данных проверяются.
- Первый снимок — тихая база сравнения, без рассылки существующих связей.
- Далее новые направленные пары `src → dst`, ещё не встречавшиеся в текущем периоде/методологии, образуют одно сводное событие на снимок. Обратная связь считается другой парой. Изменение суммы существующей пары не создаёт новый сигнал.
- Это **наблюдаемые изменения опубликованного графа**, не прогноз будущих связей и не AI-оценка виновности. Backend должен публиковать новые снимки; статичный набор данных не создаёт новых оповещений.
- При смене периода/методологии/источника создаётся новая тихая база. При недоступном/некорректном/устаревшем снимке рассылка приостанавливается, состояние сохраняется.
- Приоритет сообщения — максимальный `priority_score` узлов соответствующих связей, а не отдельный риск связи.
- История пользователя содержит только его доставленные события. Новым подписчикам и после паузы старые события задним числом не рассылаются.
- Состояние и очередь SQLite переживают перезапуск. Повторный неизменный снимок не создаёт повторное событие. Если Telegram принял сообщение, но ответ потерялся, повторная доставка возможна: это **at-least-once**, не exactly-once. Сверяйте стабильный `FG-…` ID.

## Данные и ограничения

По умолчанию `ALLOW_REAL_DATA=0`: принимаются только снимки с `_synthetic: true`. Для обработки реального снимка необходимо согласование передачи уведомлений в Telegram с владельцем данных, затем `ALLOW_REAL_DATA=1` в локальной конфигурации.

`INCLUDE_CLIENT_DETAILS=0` скрывает GID и суммы в Telegram. Даже агрегированные количества и приоритеты могут быть чувствительными; это не отменяет согласование. `INCLUDE_CLIENT_DETAILS=1` включайте только при отдельном разрешении на передачу идентификаторов и сумм.

База в `state/bot.sqlite3` содержит Telegram ID, состояния подписок, пары GID и примеры связей. Права доступа ограничены текущим пользователем, но файл **не зашифрован**. Автоматическая очистка/срок хранения, резервное копирование, банковский аудит и индивидуальный отзыв доступа ещё не реализованы. `/stop` отключает доступ, но не удаляет историю из БД. Не публикуйте `state/`.

`protect_content` ограничивает штатное сохранение/пересылку Telegram, но не гарантирует конфиденциальность. Это хакатон-MVP, не аттестованная банковская система.

## Оформление

Приветствие с зелёным логотипом Freedom Graph, структурированные карточки сообщений, цветные индикаторы приоритета и кнопки «Статус», «Последние», «Пауза», «Возобновить», «Принято к проверке». Подтверждение сохраняет отметку пользователя локально, не назначает задачу в backend и не закрывает расследование.

`design/index.html` — автономный визуальный макет личного чата, без подключения к Telegram. Реальное приложение Telegram использует тему пользователя; цвет фона чата и CSS бот не управляет. Логотип отправляется в приветствии; аватар аккаунта Telegram этим кодом не устанавливается.

`DASHBOARD_URL` — необязательная HTTPS-ссылка без секретов в URL. Если она не задана, кнопка перехода скрыта. `MIN_PRIORITY` задаёт порог 0–1, `POLL_SECONDS` — интервал 15–3600 секунд; по умолчанию 60. Есть дополнительные сетевые задержки и до 10 секунд ожидания обновлений Telegram.

## Проверка без токена и сети

```sh
python3 -m unittest TelegramBot.test_bot -v
python3 -m TelegramBot.demo
```

Тесты используют синтетические данные и подменённый транспорт: реальных сообщений не отправляют. Демо проверяет активацию → базу → новую связь → одно личное уведомление → отсутствие дубля.

```text
TelegramBot/
  __main__.py       запуск, меню, цикл проверки
  bot.py            личная активация и доставка
  config.py         локальные настройки
  engine.py         проверка снимков, сравнение, SQLite
  messages.py       тексты и кнопки
  transport.py      Telegram Bot API, read-only backend
  setup.py          скрытый ввод нового токена
  demo.py           полностью офлайн-демонстрация
  test_bot.py       автоматические проверки
  design/          макет и разрешённый логотип проекта
  .env.example     конфигурация без секретов
```

Официальная документация: [Telegram Bot API](https://core.telegram.org/bots/api), [команды и возможности ботов](https://core.telegram.org/bots/features).
