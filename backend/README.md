# Backend — pipeline и API

Все файлы бэкенда находятся в этой папке. Команды ниже выполняются из корня репозитория в терминале VS Code. Требуется Python 3.11+.

## Проверка без данных и без зависимостей

```powershell
python -m backend.run_pipeline --demo
python -m unittest discover -s backend/tests -v
```

Результат демонстрации: `backend/output-demo/`. Создаются `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`, `LATEST`, `last_attempt.json` и неизменяемый каталог запуска `runs/<run_id>/` со снимком JSON, метаданными и отчётом качества. Все gid в JSON — строки. Демо явно помечено как синтетическое и не является результатом анализа.

CSV проверяются после записи. Ошибка анализа не изменяет предыдущий опубликованный результат. При обработанной ошибке публикации корневые CSV и LATEST восстанавливаются. Одновременные запуски блокируются файлом `.pipeline.lock`. После аварийного завершения процесса этот файл можно удалить, убедившись, что pipeline больше не работает.

Несколько корневых CSV нельзя заменить одной атомарной операцией файловой системы: при внезапном выключении питания они могут относиться к разным запускам. Для согласованного чтения используйте `LATEST` и неизменяемый каталог `runs/<run_id>/`. API должен читать именно его.

## Подключение Graph Engine

```powershell
python -m pip install -r backend/requirements-graph.txt
python -m backend.run_pipeline --data ./backend/data --config ./graph/config/methodology.yaml
```

Ожидается функция `graph.analyze(data_dir, config_path)` из контракта v2.0. Она возвращает объект с `nodes`, `edges`, `clusters`, `top`, `run_meta`, `quality`. Таблицы могут быть pandas DataFrame. Входы: `nodes.parquet`, `edges.parquet`, `transactions.parquet`; проверки структуры parquet выполняет Graph Engine. Backend дополнительно сверяет покрытие gid с исходным nodes.parquet.

Graph Engine и конфиг подключены из `graph/`. Данные из предоставленного `data.zip` размещены локально в `backend/data/` и исключены из Git. На другом компьютере нужно отдельно получить архив и разместить три parquet в этой папке. Деморежим включается только явным `--demo`; ошибки реального анализа не подменяются синтетическим результатом.

Чтобы открыть настоящий результат вместо демонстрации, остановите демосервер (Ctrl+C) и запустите из корня репозитория:

```powershell
.\backend\.venv\Scripts\python.exe -m backend.run_pipeline
.\backend\.venv\Scripts\python.exe -m backend.serve
```

Откройте http://127.0.0.1:8000/check. В обзоре должны быть 2248 узлов, 3119 рёбер, 4840 транзакций и 91 кластер. Это наблюдаемые показатели данного набора, а не жёсткие ограничения программы. Первый прогон 23.09.2026 занял 28.2 с на Windows / Python 3.12.14 / 15.31 ГБ RAM. Отчёт качества: предупреждений нет, сверка транзакций с рёбрами пройдена.

Приёмочные проверки на локальных данных (A01, A10, A11, A14):

```powershell
.\backend\.venv\Scripts\python.exe -m unittest backend.tests.test_backend_real_data -v
```

Тест делает два независимых расчёта, сравнивает SHA-256 CSV, сверяет пять узлов с API и проверяет три повреждённые копии входов. Оригиналы не изменяются; временные результаты удаляются. Без локальных данных или зависимостей Graph тест пропускается с объяснением. Полный набор тестов теперь включает эти два расчёта и занимает больше времени, чем прежние синтетические проверки. Прогон 23.09.2026: A01/A10/A11 (CSV ↔ API)/A14 пройдены; два расчёта заняли 20.5 и 20.0 с. Согласованность с сайтом и ботом пока не проверена.

Коды выхода: `0` — успех, `2` — отсутствующий вход / DataValidationError, `1` — внутренняя ошибка. Поля `machine.ram_gb = 0` означают, что объём памяти определить не удалось.

## API и проверка в браузере

На этом компьютере окружение уже создано. Команды PowerShell из корня HackAlem:

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\backend\.venv\Scripts\python.exe -m backend.run_pipeline --demo
.\backend\.venv\Scripts\python.exe -m backend.serve --demo
```

Открыть http://127.0.0.1:8000/check. Нажимать «Обзор», «5 узлов», «Открыть узел», скачать CSV. Ответ HTTP 200 означает успешный запрос. В поле gid можно ввести `abc`: ожидается HTTP 400 с `invalid_gid`; `1` даёт HTTP 404 с `not_found`. Остановка сервера — Ctrl+C в его терминале. Страница работает без внешних скриптов и CDN.

Демонстрация содержит 24 синтетических изолированных узла, поэтому список связей пустой. Обход связей проверяется отдельно в автоматических тестах на синтетической цепочке. Это ещё не результат анализа реальных переводов.

На другом компьютере сначала установите Python 3.11+ и выполните `python -m venv backend/.venv`, затем команды выше. Встроенное окружение этого компьютера зависит от локального Python и не переносится через Git.

```powershell
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
```

Основные запросы: `/api/v1/health`, `/overview`, `/graph`, `/nodes`, `/nodes/{gid}`, `/nodes/{gid}/neighbors`, `/subgraph`, `/top`, `/clusters`, `/clusters/{id}`, `/export/{name}`. Все пути имеют префикс `/api/v1`. Полная схема параметров — `/openapi.json`.

После нового расчёта нажмите «Перечитать результат» (`POST /api/v1/reload`). API и выгрузки используют один загруженный запуск до reload. Ошибка reload сохраняет предыдущий снимок в памяти.

Без `--demo` сервер использует `backend/output` или переменную окружения `OUTPUT_DIR`. Если результата нет, health/overview продолжают работать, запросы к данным возвращают `no_result` (503). Запуск через `python -m backend.serve` читает `backend/.env`; уже заданные переменные терминала имеют приоритет. При прямом запуске через uvicorn переменные нужно задать отдельно. Порт можно изменить: `--port 8001`. Готовая сборка `Frontend/dist` отдаётся на `/`, если она есть; `/check` остаётся доступен. Фронтенд пока не переведён с mock-данных на API.

`requirements.txt` фиксирует проверенное окружение API и тестов; `requirements-graph.txt` подключает зависимости Graph Engine, которыми управляет его разработчик.

## AI-агент: включение и проверка

Backend подключает существующий `graph.assistant.Assistant`, не дублируя алгоритмы и агентный цикл. Реализован `POST /api/v1/assistant` с `question` (1–4000 символов) и необязательным `history` (до 6 сообщений с role=user/assistant и content до 4000 символов). Ответ: `answer`, `gids`, `tool_calls`, `mode: ai`, `run_id`. Агент фиксирует один снимок на весь вопрос, даже если параллельно происходит reload. HTTP-клиент закрывается после каждого запроса.

Обновление: поддерживаемый агент теперь находится в `ai_agent/`, а `graph.assistant` сохраняет совместимый импорт. Агент исправляет неподтверждённый черновик в пределах прежнего лимита шагов. Для единственного успешного `get_top` бэкенд выводит весь список инструмента (до 20 строк) с точными значениями из данных, без округления моделью и ограничения отчёта тремя карточками. Поле `answer_source: tool_result` обозначает такой вывод; модель по-прежнему выбирает инструмент и параметры. Неизвестные GID и неподтверждённые черновики не передаются пользователю. Новая проверка покрывает запрос топ-10 с ошибочным черновиком «985 тыс» вместо 984635.0.

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements-assistant.txt
```

Если `backend/.env` ещё нет, скопируйте в него `backend/.env.example`. В локальном `.env` заполните:

```dotenv
ASSISTANT_ENABLED=1
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=идентификатор_доступной_модели
```

Ключ хранится только на сервере, не вводится в чат или HTML и исключён из Git. Не используйте буквальные значения-заглушки выше. Выберите доступную вашему API-проекту модель с Responses API и function calling. После изменения `.env` перезапустите сервер:

```powershell
.\backend\.venv\Scripts\python.exe -m backend.serve
```

Откройте `/check`, обновите страницу и найдите «AI-ассистент аналитика». Примеры вопросов: «Покажи 5 приоритетных узлов и объясни причины», «Объясни роль узла #<gid>», «Есть ли путь от #<gid1> до #<gid2>?». В раскрывающемся блоке видны выбранные агентом инструменты; кнопки GID открывают карточки. «Новый разговор» очищает историю; история хранится только в памяти страницы. При смене запуска история сбрасывается.

`/health` возвращает `assistant_enabled` и понятное `assistant_message` без ключа. Значение true означает наличие настроек и зависимостей, но не проверяет баланс, действительность ключа или доступность модели. Запрос к провайдеру происходит только при отправке вопроса; он может тарифицироваться. В модель уходят вопрос, до 6 предыдущих сообщений и результаты выбранных инструментов, а не весь снимок.

Без настроек возвращается `assistant_disabled` (503). Некорректный вопрос — `invalid_param` (400), отсутствие снимка — `no_result` (503), сбой провайдера/таймаут/отклонённый ответ — `internal` (500). Ошибки агента не изменяют CSV и не останавливают API. Ограничения Graph-агента: 30 секунд, до 5 шагов и вызовов инструментов. Проверка ответа на числа/GID — дополнительный фильтр, а не гарантия правильности интерпретации.

Интеграция проверена без сети с подставным ответом провайдера и настоящим Graph-агентом: выбор инструмента, получение данных, ответ, история/валидация, ошибки, таймаут, лимит шагов и закрытие клиента. Это не проверка живой модели. Для тестов:

```powershell
.\backend\.venv\Scripts\python.exe -m unittest backend.tests.test_backend_assistant -v
```

Схема обмена инструментами: [официальная документация OpenAI](https://developers.openai.com/api/docs/guides/function-calling).

Важное отличие от исходного плана: по договорённости с владельцем бэкенда точка входа, тесты, окружение и результаты расположены внутри `backend/`; запуск — `python -m backend.run_pipeline`.


## PDF-досье

В интерфейсе: «Расследование» → «Досье» → добавить факты → «Скачать PDF».
Отчёт содержит выбранные узлы, связи и направленные цепочки, даты, суммы,
ID снимка, проверку хронологии и ограничения наблюдения. Русский шрифт встроен
в файл; внешние сервисы и API-ключ не нужны.

`POST /api/v1/export/report.pdf`: JSON с `run_id` и `keys` (от 1 до 30 ссылок).
Ссылки: `node:GID`, `edge:SRC:DST`, `path:SRC:DST|DST:NEXT` (до 6 связей).
Факты берутся из серверного снимка, клиентский текст не принимается.
Ответ: `application/pdf`, attachment и `Cache-Control: no-store`.
Смена снимка возвращает 409: нужно обновить данные и собрать досье заново.
Отсутствующие ссылки и несвязные цепочки возвращают 400.

После обновления установите `pip install -r backend/requirements.txt` в окружении
бэкенда и перезапустите `python -m backend.serve`. Зависимость `reportlab`
и шрифт `backend/assets/fonts/DejaVuSans.ttf` нужны для экспорта.
