# Что осталось владельцу Graph + AI

Основание: исходное ТЗ HackAlem «Граф денег», PROJECT (2).md v1.1, CONTRACT_AI 2.0 и уточнение пользователя: Graph и агент принадлежат ему, backend и frontend делают два других участника. Этот файл — рабочий чек-лист и не заменяет контракт.

## 1. Готовая графовая часть

Есть analyze(), валидация трёх parquet, направленные признаки, компоненты, Louvain, шесть ролей, score, приоритет, evidence/why, координаты. Проверенный датасет: 2248 узлов, 3119 рёбер, 4840 транзакций, 91 кластер; исходные GID сохранены, граница защищена от ложного terminal. Пользовательский прогон дал 11.07 с, repeat_verified=true и warnings=[]. Это подтверждает воспроизводимость реализации, не accuracy ролей: разметки нет.

Не нужно переписывать ядро или подгонять распределение ролей под предварительные числа. Время/циклы/устойчивость — дополнительные исследования ТЗ §8, а не недостающий обязательный Graph функционал. До готовности сквозного сценария не расширяйте объём ими.

## 2. Передать интерфейсы двум участникам

Backend: `graph.analyze(data_dir,config_path)`; текущий путь конфигурации `graph/config/methodology.yaml`; на выходе AnalysisResult. Для живого агента использовать `python -m ai_agent --output backend/output --env-file ai_agent/.env` либо ai_agent.api.install в своём приложении. Текущий backend уже вызывает агент через совместимый импорт graph.assistant. Обёртка ai_agent заменяет этот маршрут и добавляет виджет; второго одинакового маршрута не создаётся.

Frontend: перейти с mockData на API, сохранять gid строками и score [0,1]; добавить `ai_agent/ui/AssistantPanel.tsx` или web component. Связать `graph-node-select` с поиском/выделением узла и сбросом скрывающих фильтров. Карточка должна показывать рассчитанное evidence и ограничения; утверждения о часах убрать, поскольку исходные данные содержат только даты.

Окончательная работа сайта и публикация backend — зона соответствующих участников. Для проверки Graph уже есть отдельный offline viewer; для AI — `/assistant`. Эти экраны не подменяют интеграционную приёмку сайта команды.

## 3. Проверить объяснимость перед защитой

- Выбрать два примера каждой роли, изолят, seed и узел depth=4 из фактического результата.
- Для каждого объяснить: какие признаки наблюдаются, какое правило/порог сработало, почему эта роль победила альтернативные, какие ограничения влияют на вывод.
- Различать role_score (соответствие правилу) и priority_score (очерёдность проверки). Ни один из них не вероятность виновности.
- Быть готовым объяснить три произвольных GID за минуту по карточкам — это прямое требование must have 3.
- Зафиксировать methodology.yaml; любое изменение порогов передать backend и повторить публикацию снимка. Клиенты не должны иметь свои формулы.

## 4. Завершить AI

Создать настоящий API-ключ, сохранить локально в ai_agent/.env, выбрать доступную модель Responses/function calling. По исходному DOCX §8 AI опционален; по вашему новому поручению он обязателен в нашей поставке. Даже после включения AI отсутствие сети/ключа не должно ломать P0.

Проверить живые вопросы: «кого смотреть первым», «почему эта роль», «кто собирает с пяти seed», «какой путь между двумя узлами», «почему depth=4 нельзя уверенно считать конечным получателем». Для ответа о пяти seed убедиться, что вызван common_downstream; если exact_intersection=false, ответ обязан сказать, что общего узла для всех не найдено. Если срезаны результаты, это должно быть отражено в объяснении.

Вопросы на странице формируются из реальных GID, без хардкода кандидатов. Окончательный выбор примеров для демо делается после просмотра результата. Нельзя заменять неработающий LLM подготовленными текстами и выдавать их за живой ответ.

## 5. Совместная приёмка и сдача

С backend сверить пять любых GID: CSV = API = карточка сайта по роли/score/кластеру/run_id. С frontend найти изолят, граничный узел и узел, скрытый фильтром. Без сети сайт и CSV должны работать. При сбое нового запуска предыдущий результат должен сохраниться. Сбой OpenAI не должен влиять на топ и граф.

Ваш комплект: код Graph + AI, методика, результаты реального расчёта, ограничения, раздел масштабирования и схема «данные → признаки → роли → снимок → сайт/AI». README и INTEGRATION уже содержат методику/схему; три CSV формирует pipeline команды. Исходный датасет и ключ не публикуются.

Пятиминутное демо команды: 30 секунд цель и ограничения; до минуты живой расчёт; 2 минуты три узла (включая границу/изолят); минута вопрос AI о нескольких seed и переход к карточке; 30 секунд архитектура и ограничения. Ваша речь должна опираться на реальные значения карточек, а не на заученные GID.

Готовность вашей части: воспроизводимый расчёт + объяснимость произвольного узла + согласованные интерфейсы + действительный живой ответ агента с проверяемыми ссылками. Готовность всего продукта дополнительно требует сайта и backend; она не подтверждается одними тестами Graph.
