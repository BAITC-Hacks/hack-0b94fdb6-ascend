# AI Agent — помощник аналитика на сайте

Агент отвечает на вопросы по одному готовому снимку графа. Главный сценарий из ТЗ §8: «кто собирает деньги с этих пятерых?» → ограниченный обход направленного графа → объяснение со ссылками `#gid`. Другие сценарии: объяснение роли и ограничений узла; соседи; общие источники; пути; Top-N; кластер; сравнение двух карточек несколькими вызовами get_node.

В исходном DOCX и PROJECT 1.1 AI — дополнительный объём. По прямому поручению владельца Graph+AI от 23.09 он включён в нашу поставку. Обязательная аналитика сохраняет автономность: без ключа или сети роли, evidence, CSV, граф и API продолжают работать.

## Быстрая проверка на уже рассчитанном снимке

Все команды выполняются из корня репозитория. Для существующего виртуального окружения Windows:

```bat
.\.venv\Scripts\python.exe -m pip install -r ai_agent/requirements.txt
.\.venv\Scripts\python.exe -m ai_agent --snapshot .\check-result\snapshot.json
```

Открыть `http://127.0.0.1:8000/assistant`. Без ключа отображается «Ассистент отключён», кнопка отправки неактивна. Реальные карточки и подсказки вопросов работают без LLM. Этот режим предназначен для отдельной проверки агента: основной API backend остаётся привязан к опубликованному backend/output, а агент — к явно выбранному файлу. Для совместного сайта используйте следующий режим, в котором все клиенты читают один снимок.

## Полный сайт и агент на общем backend

```bat
.\.venv\Scripts\python.exe -m backend.run_pipeline --data "D:\Хакатон ИИ Агент\data" --config graph/config/methodology.yaml
.\.venv\Scripts\python.exe -m ai_agent --output backend/output --env-file ai_agent/.env
```

`python -m ai_agent` запускает существующий backend и подключает к нему маршруты агента. Обработчик `/api/v1/assistant` заменяется расширенным обработчиком агента, в health отображается актуальный флаг включения. Старые API, CSV, reload и раздача Frontend/dist сохраняются. Исходники backend и Frontend этой поставкой не изменяются. Если порт занят, добавьте `--port 8001` или остановите предыдущий сервер. Приложение слушает только 127.0.0.1.

## API-ключ и модель

Создать локальный `ai_agent/.env` по `.env.example`:

```dotenv
ASSISTANT_ENABLED=1
OPENAI_API_KEY=your-secret-api-key
OPENAI_MODEL=your-available-model-id
```

Реальный ключ создаётся в [API keys](https://platform.openai.com/api-keys). Ссылка на проект/приглашение не заменяет секретный ключ. Модель должна быть доступна этому ключу и поддерживать Responses API/function calling. Значение по умолчанию не навязывается. `.env` читается только при явном `--env-file`; переменные окружения имеют приоритет. Ключ никогда не передаётся в браузер, health, JSON-ответы или Git; `.gitignore` исключает локальные env-файлы. Не копируйте реальный ключ в `.env.example`.

## Подключение в сайт участника frontend

Готовый виджет без дополнительных JS-библиотек:

```html
<script src="/ai-agent/assistant.js" defer></script>
<moneygraph-assistant api-base="/api/v1"></moneygraph-assistant>
```

Для React готов `ui/AssistantPanel.tsx`. Участник frontend копирует его в `Frontend/src/components` и добавляет:

```tsx
<AssistantPanel selectedGid={selectedNode.gid} onSelectGid={selectNodeByGid} />
```

`selectNodeByGid` должна найти реальный узел по строковому gid, сбросить скрывающие его фильтры и открыть карточку. Выбор узла только подставляет вопрос — платный запрос не отправляется автоматически. В Vite проксировать `/api` и `/ai-agent` на `http://127.0.0.1:8000`; в собранном сайте используется тот же origin.

Без React ссылка `#gid` ведёт на `/#/node/<gid>`. Для своей навигации подпишитесь на событие `graph-node-select`, прочитайте `event.detail.gid` и вызовите `event.preventDefault()` после обработки. Не преобразовывайте gid в Number.

Страница `/assistant` — готовый экран приёмки с чатом и независимой карточкой фактов. Ответы/вопросы вставляются через textContent, не исполняются как HTML; ссылки создаются только для проверенных gids. История живёт только в памяти вкладки, ограничена шестью сообщениями; при смене run_id она очищается. Показаны ожидание, ошибки, отсутствие ключа, отсутствие данных. Есть кнопки вопросов, построенные из реального снимка, включая пять seed одного кластера при их наличии.

## Подключение владельцем backend

Если участник backend хочет сохранить собственную точку запуска, перед окончанием create_app:

```python
from ai_agent.api import install
install(app, lambda: app.state.snapshot.data if app.state.snapshot else None,
        replace_disabled=True)
```

`replace_disabled=True` явно разрешает заменить существующий обработчик (имя параметра сохранено для совместимости). Вызывать один раз. Маршруты вставляются перед catch-all раздачей frontend, поэтому `/assistant` не скрывается StaticFiles. В этом варианте участник backend должен обновить `assistant_enabled` в своём health через `ai_agent.config.enabled()`. Готовая обёртка `ai_agent.app.create_app` уже делает это. При reload следующий вопрос получает новый снимок; текущий вопрос завершает работу с копией прежнего снимка.

## Контракт и дополнительные маршруты

Основной контракт неизменен: `POST /api/v1/assistant`, запрос `{question,history?}`, обязательные поля ответа `{answer,gids,tool_calls,mode:'ai'}`. Дополнительное поле `run_id` сохранено для совместимости с обновлением backend 9f6ad1d. Заголовок `X-Analysis-Run-Id` отмечает снимок ответа. Ошибки: invalid_param/400, no_result/503, assistant_disabled/503, internal/500, как в CONTRACT_AI. Ошибка LLM не отменяет опубликованные CSV или снимок.

Дополнения только для виджета, не заменяют API команды: `GET /api/v1/assistant/status` (enabled,ready,run_id), `/assistant/suggestions` (готовые вопросы), `/assistant/node/{gid}` (карточка фактов). Их не нужно вызывать модели. `/assistant` отдаёт экран, `/ai-agent/assistant.js` — код виджета.

Поддерживаемая реализация — `ai_agent/service.py`. Графовые операции — `graph/query.py`. Старые `graph.assistant` и `graph.integration.backend_assistant` остаются совместимыми обёртками, второй независимой реализации нет. Новая папка ai_agent создана по прямому запросу пользователя; это явное обновление размещения по сравнению с backend/assistant из исходного контракта. Общий CONTRACT_AI не переписан.

## Ограничения и проверяемость

Семь инструментов: get_node, get_neighbors, common_downstream, common_upstream, find_paths, get_top, get_cluster. Они читают готовые агрегаты; сырые транзакции и весь граф не отправляются модели. Ограничения: 5 шагов модели, до 5 вызовов инструментов, 30 секунд на обработку, до 2 одновременных запросов; до 20 соседей/топ-узлов, до 10 начальных gid, глубина 4, до 5 путей длиной до 6 рёбер. Ограниченный результат помечается truncated; неполное пересечение — exact_intersection=false. Достижимость не доказывает, что двигались одни и те же деньги.

Реализован Responses API с `store=False`, отключёнными повторными запросами SDK и сохранением всех элементов ответа, включая reasoning items, внутри одного инструментального цикла. Основание: [function calling](https://developers.openai.com/api/docs/guides/function-calling) и [reasoning](https://developers.openai.com/api/docs/guides/reasoning) в официальной документации OpenAI. store=False не следует понимать как заявление о политике хранения всех служебных данных провайдера.

Сервер проверяет GID, числовые значения (с учётом эквивалентного десятичного форматирования), длину ответа и запрещённые обвинительные формулировки. Это не доказательство семантической истинности: совпадение числа само по себе не исключает неверную связь с фактом. Аналитик должен проверять карточки и список использованных инструментов. Слишком свободное округление/пересчёт моделью отклоняется. Агент не меняет роли/score и не генерирует обязательные CSV/evidence.

## Проверка без сети и живое демо

```bat
.\.venv\Scripts\python.exe -m pip install -r graph/requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest graph/tests ai_agent/tests backend/tests -q
```

Автотесты используют подставной клиент Responses, но настоящие графовые операции. Проверяются route replacement, снимок и reload, изоляция сбоев, лимиты, ошибки ввода, grounding, таймаут, reasoning items, история, конфигурация, одновременные запросы. В тестах нет настоящего ключа и внешних вызовов.

Для живой приёмки после настройки ключа: открыть `/assistant`, нажать вопрос о пяти seed, отправить, увидеть ответ и tool_calls с common_downstream, перейти по GID, сверить карточку. Затем объяснить узел depth=4, изолят и неизвестный GID; проверить ошибку провайдера и работоспособность `/api/v1/top` после неё. Живая проверка не объявляется завершённой до успешного вызова с вашим действительным ключом и моделью.

После обновления backend 9f6ad1d его обычная точка запуска также использует новый агент через совместимый импорт graph.assistant. Для нашего виджета и маршрутов карточек запускайте ai_agent; одновременно два сервера на одном порту запускать не нужно. Страница backend /check сохраняет совместимость по run_id и assistant_message.
